# QA 리포트 — 사용자 플레이테스트 (2026-07-03)

로컬 플레이테스트 서버(`http://127.0.0.1:8787`, `public/game/index.html`)에서 실플레이 후 접수된 피드백 5건.
각 항목에 증상 → 원인 분석(코드 위치) → 제안 수정 → 우선순위를 정리한다. **이 문서는 구현 지시서가 아니라 QA 분석서**이며, 실제 구현은 Codex 작업으로 넘긴다.

## QA-1. 판정/능력치 이름이 영어로 노출됨 (Sneaky, Fast 등)

**증상**: 플레이 중 능력치·주사위 판정 이름이 `Sneaky`, `Fast` 같은 영어 키로 표시된다.

**원인 분석**:
- 한국어 라벨 자체는 이미 존재한다. `src/services/sheet-schema.ts:566-581`에 `Sneaky→은밀함`, `Fast→재빠름`, `Tenacious→집요함` 매핑이 정의되어 있고, 서버도 판정 브로드캐스트 시 `attributeLabel`을 채워 보낸다(`src/realtime/room-orchestrator.ts:1081-1091`).
- 누수 경로는 두 갈래로 추정:
  1. **클라이언트 폴백 누락**: `public/game/index.html:1282`의 `ATTR_LABELS`가 EZFudge 4종(Might/Agility/Wits/Spirit)만 커버한다. `attributeLabel`이 비어 오는 경로(시나리오 미선택 등, `room-orchestrator.ts:1082`의 `scenario !== null` 가드 참고)에서는 geese 스탯이 영어 키 그대로 폴백된다.
  2. **AI GM 서술 자체에 영어 키 사용**: `src/services/scenario-service.ts:201`의 시나리오 프롬프트가 스탯을 `"Sneaky(은밀·몰래 접근), Fast(재빠름·기습·도주)…"` 형식으로 소개하므로, GM이 나레이션 본문에 영어 키를 그대로 쓸 수 있다. 이 경로는 UI 라벨 매핑으로는 못 잡는다.

**제안 수정**:
- 클라이언트 `ATTR_LABELS`에 geese 3종 추가(단기), 또는 스키마의 trait 라벨 맵을 세션 시작 시 클라이언트로 내려 폴백을 스키마 기반으로 통일(권장).
- 시나리오 프롬프트에 "판정·능력치를 서술에 언급할 때는 반드시 한국어 라벨(은밀함/재빠름/집요함)을 사용하라"는 지시를 추가.

**우선순위**: 중 — 몰입 저해지만 기능 자체는 동작.

## QA-2. 위로 스크롤해도 강제로 맨 아래로 끌려 내려가는 버그

**증상**: 지난 텍스트를 읽으려 스토리 영역을 위로 스크롤해도, 갱신이 일어나면 강제로 맨 아래로 고정된다.

**원인 분석**: 렌더링 때마다 무조건 `scrollTop = scrollHeight`를 실행한다. 사용자가 현재 하단에 있는지 확인하는 로직이 없다.
- `public/game/index.html:774` (스토리 패널), `:966` (사이드 로그)
- `public/game/ai.html:200, 207, 359`
- `public/quickplay/index.html:114`
- `public/game/scenario.html:194, 202`

스토리 패널은 `replaceChildren`으로 전체 재렌더링하므로 상태 갱신(로스터 변경 등)마다 스크롤이 리셋된다 — 새 텍스트가 없어도 끌려 내려간다.

**제안 수정**: 표준 "stick-to-bottom" 패턴 적용. 렌더 전에 `사용자가 하단 근처(예: scrollHeight - scrollTop - clientHeight < 40px)인지` 판정하고, 하단일 때만 자동 스크롤. 위로 스크롤한 상태에서 새 메시지가 오면 "새 메시지 ↓" 점프 버튼을 띄우는 것까지 하면 이상적. 위 나열된 모든 파일에 동일 패턴 적용 필요.

**우선순위**: **상** — 명백한 버그이고 읽기 경험을 직접 파괴함. 수정 난이도 낮음.

## QA-3. 굴리기 버튼이 있는데 시스템이 먼저 굴려버림 → 순서 기반 개인 굴림 제안

**증상**: 주사위 굴리기 버튼이 표시되지만 누르기 전에 시스템이 강제로 굴려버린다.

**원인 분석**: 플레이어 개인 굴림 흐름 자체는 구현되어 있다 — 본인 판정에만 굴리기 버튼이 뜨고(`public/game/index.html:1328-1354`), `ROLL_CHECK` 커맨드로 서버에 전송된다(`src/realtime/room-orchestrator.ts:126, 412`). 문제는 **자동 굴림 타임아웃이 20초**라는 것(`src/core/config.ts:38`, `rollCheckTimeoutMs: 20000`). GM 나레이션을 읽는 데만 20초가 넘게 걸리므로, 사용자가 버튼을 인지하기 전에 타이머가 만료돼 서버가 대신 굴린다(`room-orchestrator.ts:969-972`). 또한 모든 판정이 동시에 열려서 "누가 굴릴 차례인지"가 없다.

**제안 수정**:
1. `rollCheckTimeoutMs`를 대폭 상향(예: 60-90초) 또는 "전원 대기, 호스트가 스킵 가능" 모델로 전환. 최소한 타임아웃 진행 상황(카운트다운)을 UI에 표시해 예고 없는 강제 굴림을 없앤다.
2. 사용자 제안대로 **턴 순서 기반 순차 굴림**: 판정을 한 번에 하나씩 열고, 현재 굴릴 플레이어를 턴 인디케이터(`renderTurnIndicator`, `public/game/index.html:995`)에 표시. 이미 턴 순서 인프라(`phaseModel.turnOrder`)가 있으므로 재활용 가능.

**우선순위**: 상 — 핵심 상호작용(주사위)이 플레이어 손을 떠나 있어 "내가 굴렸다"는 감각이 없음.

## QA-4. 마주치지 않은 NPC까지 상단 블랙보드에 전부 표시됨

**증상**: 아직 만나지 않은 NPC도 게임 상단 블랙보드 바에 처음부터 모두 노출된다. 스포일러이자 정보 과잉.

**원인 분석**: 플레이어용 블랙보드 projection이 NPC를 필터링하지 않는다. `src/core/scenario-blackboard.ts:247`의 `toVisibleBlackboard`가 `bb.npcs`를 **전부** 매핑해 내려보내고, 클라이언트는 받은 것을 그대로 그린다(`public/game/index.html:895-902`). `NpcState` 타입(`scenario-blackboard.ts:28`)에는 "만났음/공개됨" 개념 자체가 없다 — 단서(clue)는 `discovered` 게이팅이 있지만 NPC에는 대응물이 없다.

**제안 수정**: `NpcState`에 `encountered: boolean`(또는 `revealed`) 필드 추가. 시드 시점엔 false, GM이 해당 NPC를 장면에 등장시킬 때 reveal delta(`npc_revealed` 등 신규 BlackboardDelta)로 true 전환. `toVisibleBlackboard`에서 `encountered === true`만 projection. 기존 델타 리듀서(`scenario-blackboard.ts:174-204`)의 fail-closed 패턴을 따라 추가.

**우선순위**: 중 — 스포일러 문제이므로 시나리오 미스터리성(until-it-sinks 등)에 직접 영향.

## QA-5. 응답 대기가 지루함 → 글자 단위 실시간(스트리밍/타자기) 출력 제안

**증상**: AI GM 응답을 통째로 기다리는 동안 화면에 아무 변화가 없어 지루하다.

**원인 분석**: GM 두뇌가 CLI 단발 실행(`codex exec` / `claude -p`) 결과를 통째로 받아 한 번에 브로드캐스트하는 구조라, 응답 생성 시간(수십 초) 동안 클라이언트에 아무것도 도착하지 않는다.

**제안 수정** (비용 낮은 순):
1. **클라이언트 타자기 효과**: 완성된 나레이션을 받아 글자 단위로 순차 출력. 서버 변경 없음. 체감 대기시간은 그대로지만 "도착 후 읽는 경험"이 좋아지고, 출력 중 스킵(클릭 시 전체 표시) 넣기 쉬움.
2. **진행 인디케이터 강화**: 생성 중 "GM이 서술을 쓰는 중…" 타이핑 표시 + 경과 시간. 1과 병행 가능.
3. **진짜 스트리밍**: `claude -p --output-format stream-json`(Claude CLI) 등 스트리밍 출력을 WS로 릴레이. 체감 개선이 가장 크지만 CLI 클라이언트 계층(`src/ai/claude-cli-client.ts`, `codex-cli-client.ts`)과 브로드캐스트 경로 재설계가 필요하고, codex CLI 쪽 스트리밍 지원 여부 확인 필요. 별도 과제로 분리 권장.

**우선순위**: 중 — UX 개선 요구. 1+2를 단기, 3을 중기로.
