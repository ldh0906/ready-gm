## 1. 비전 (아이디어 노트에서 확정된 것)

**AI가 TRPG의 GM을 맡고, 친구들이 원격으로 모여 함께 즐기는 웹 서비스.**

- **타깃**: 친구 그룹(서로 아는 사람끼리 방을 만들어 플레이). 불특정 매칭 아님.
- **Phase 1 성공 기준**: *"친구 4명이 2시간 한 판(원샷) 하고 재밌었다."* — 이 문장이 모든
  우선순위의 최상위 심판이다. 원샷이 재미없으면 캠페인·UGC·수익화 전부 무의미하다.
- **깔때기**: 원샷(재미 검증) → 캠페인(리텐션) → UGC 시나리오(해자). UGC는 방향은 맞지만
  1일차 기능이 아니다.
- **차별점(무기)**: ① UGC 시나리오(진짜 해자) ② 한국어 네이티브 GM ③ "친구끼리 모여 노는
  밤" 동시접속 경험 ④ 세션당 과금 ⑤ 장면 박제 일러스트(바이럴 훅).
- **진행 방식**: 레디체크 하이브리드(자유 수다 → 전원 확정/패스 → GM 일괄 서술). AFK
  자동 패스, 방장 강제 진행.

## 2. 현실 점검 — 2026-07-03 자동 플레이테스트에서 배운 것

(근거: `out/qa/qa-2026-07-03-e2e-playtest.md`의 "고객 관점 총평")

**이미 이긴 것**: 한국어 서사 품질은 상용 수준이고, 플레이어 행동을 빠짐없이 존중한다.
판정·재접속·권한 같은 기반은 견고하다. — "AI가 글을 잘 쓰는 서비스"까지는 왔다.

**아직 진 것**: "친구들과 게임하는 기분"이 안 난다.
① 결과 대기 중 화면이 침묵한다(25~50초, 실패 시 수 분). ② 하필 그 대기 시간에 채팅이
잠긴다 — 친구들이 떠들 순간을 시스템이 막는다. ③ 전원확정→일괄서술 구조라 GM과의
주고받는 대화감이 없다(편지 왕복). ④ 라운드 호흡이 균질해서 몇 라운드면 리듬이 예측된다.

## 3. 판단 원칙 (기능 심사 기준)

1. **침묵은 버그다.** 플레이어 화면이 10초 이상 아무 변화 없으면 그 자체가 결함이다.
   진행 중이면 "무엇을 하는 중인지", 실패했으면 "실패했고 어떻게 되는지"를 즉시 보여준다.
2. **기다림에도 놀이가 있어야 한다.** AI 지연을 0으로 만들 수 없다면, 그 시간을 사회적
   시간(잡담·리액션·지난 기록 구경)으로 바꾼다. 대기 중 입력 잠금은 원칙 위반.
3. **GM은 서술자이기 전에 대화 상대다.** 장기적으로 되물음·짧은 응답(ask_world/table_talk
   라우팅 — 아이디어 노트의 intent 분류 참조)을 향해 간다. "좋은 소설"보다 반응성.
4. **상태 권위는 엔진, AI는 제안.** (기술 불변식이자 제품 신뢰의 근간 — 환각으로 진행이
   꼬이는 순간 친구 모임의 밤이 망한다.)
5. **한국어 네이티브.** 번역투·영어 키 노출은 결함으로 취급한다.
6. **친구 그룹 최적화.** 익명 대중용 기능(매칭·랭킹 등)은 만들지 않는다. 방장이 열고
   친구가 링크로 들어오는 동선을 항상 최단으로.

## 4. 체감 예산 (측정 가능한 목표)

| 지표 | 목표 | 현재(2026-07-03 실측) |
|---|---|---|
| 행동 확정 → 첫 피드백(판정 선언 or 진행 표시) | ≤ 5초 (표시), ≤ 30초 (판정) | 15~100초, 표시 빈약 |
| 굴림 완료 → 결과 서사 시작 | p50 ≤ 20초, p90 ≤ 60초 | 4~46초 (실패 시 5분+) |
| 화면 무변화 침묵 상한 | 10초 | 위반 다수 (실패 경로는 90초+) |
| 실패 발생 → 사용자 인지 | 즉시 (배너) | 무한 (첫 실패 무음) — 수정 T-1 |
| 한 라운드 총 소요 (4인 기준) | 3분 내 | 미측정 (2인 1~3분, 실패 시 초과) |

측정 방법: `round_timing` QA 이벤트 + E2E 하네스 로그. 릴리스 전 회귀 체크에 포함.

## 5. 로드맵 (아이디어 노트 Phase와 정렬)

### Now — "결함 없는 원샷" (Phase 1 마감)
- T-1 실패 가시화+즉시 재시도, T-2 오프닝 게이트, T-3 거위 시드 정합
  (지시서: `out/qa/qa-2026-07-03-e2e-playtest.md`)
- P-1 대기 중 잡담 허용, P-2 단계별 진행 표시 — 원칙 1·2의 최소 구현
- 클라이언트 모듈 분리 (`out/specs/impl-2026-07-03-game-client-split-spec.md`) — 이후 UI
  작업 속도의 토대

### Next — "대화감과 밤의 완성" (Phase 1.5)
- **스트리밍 중계**: CLI 단발 호출 → 토큰 스트림 릴레이로 서사가 실시간으로 흐르게
  (타자기 효과의 실제화). 침묵 예산을 구조적으로 해결.
- **intent 라우팅 1단계**: 대기 중 잡담(table_talk)과 세계 질문(ask_world)을 구분해,
  가벼운 질문은 판정 없이 짧게 즉답 — 편지 왕복을 대화로 바꾸는 첫 걸음.
- **호흡 다양화**: climactic 라운드만 서술 길이·연출 격상(아이디어 노트의 "클라이맥스
  에스컬레이션"), 평시는 더 짧고 빠르게.
- 엔딩 경험 검증(완주 QA) — "한 판 끝났다"의 만족감.

### Later — Phase 2~3 (아이디어 노트 그대로)
- 세션 결제 + 장면 박제 일러스트(재화) → 캠페인(장기기억: Memory Clerk·Front Planner
  분리, 2층 메모리+RAG) → 수동 큐레이션 시나리오 → UGC 에디터 → 랜덤 생성창.
- 멀티모델 라우팅(국면=고성능/핫패스=중간/요약=저가)은 **구조가 먼저, 모델 분리는 비용
  최적화 문제** (ai-architecture.md의 결론 유지).
